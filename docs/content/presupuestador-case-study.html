Fig. 01 — Context

A workshop that quotes well — just slowly, and from one person's head.

Guzmán Villalba is a metal fabrication workshop in Montevideo. Every job — from a custom staircase railing to a full production run of parts — starts with a quote. For years, that quote came from one estimator's judgment: material, labor, machine time, and margin, priced from memory and experience, not from a written system.

That worked, until it didn't scale. Quotes queued up behind one person. New team members couldn't estimate without shadowing him for months. And because the logic lived in his head, it couldn't be questioned, versioned, or improved — only repeated.

Fig. 02 — Problem

Slow estimates cost jobs before any metal is cut.

Clients calling for a rough number would often go quiet for days while waiting on a formal quote — and take the job elsewhere. The workshop needed to answer fast with a defensible range, then follow up with a precise number, without the whole process depending on a single calendar.

Fig. 03 — Discovery

Watching quotes get built, not just asking how they get built.

Interviews alone undersold how much judgment was involved — the estimator himself struggled to articulate his own rules. Shadowing several real quotes end to end surfaced the actual inputs: material type and thickness, cut complexity, finishing steps, machine availability that week, and a margin that flexed based on client relationship and urgency.

The clearest finding: the logic wasn't random, it was consistent but undocumented — which meant it could be captured as an explicit model instead of replaced with a generic pricing formula that would have ignored real workshop constraints.

Fig. 04 — System architecture

One pricing model, three surfaces.

Rather than building a single monolithic app up front, the system separates the pricing logic (versioned, inspectable, owned by the workshop) from the surfaces that read it — so the estimator could keep working day one, and the interface could evolve independently of the math underneath.

Inputs (material, dimensions, finish, urgency) feed a single pricing model. That model outputs both a fast orientative range and, once confirmed, a full itemized quote. The same model is queried from the Sheets MVP and, later, from the Alpha app — so switching surfaces never means re-deriving the logic.

Fig. 05 — MVP / Sheets

Ship the logic before the interface.

The first version of the pricing model lived entirely in Google Sheets with Apps Script — deliberately, so the estimator could correct and extend the logic himself without waiting on a development cycle, and so the system could be validated against real quotes before any UI was built.

presupuestador.xlsx — pricing model v1
{asset: mvp-sheets-screenshot}

Every quote run through the Sheet was logged and compared against the estimator's own gut-check number. Disagreements weren't treated as MVP bugs to hide — they were the signal used to refine the model's weighting before moving to a dedicated interface.

Fig. 07 — The role of AI

AI assists the estimate. It never silently sets the price.

AI is used in three narrow, inspectable places — each one assistive, each one overridable by the person running the quote.

01

Reading raw input

Task
Extract dimensions/material notes from a photo or a client's free-text description.
Guardrail
Always shown back to the estimator as editable fields before pricing runs.
02

Suggesting a range

Task
Propose an orientative price range from historical quotes with similar inputs.
Guardrail
Labeled explicitly as a suggestion; the pricing model's own logic is the final number.
03

Flagging anomalies

Task
Flag a quote that falls far outside the historical pattern for review before sending.
Guardrail
Advisory only — never blocks sending a quote, only asks for a second look.
Fig. 08 — Limitations

What the system doesn't do yet.

Working today
  • Fast orientative range for common job types
  • Shared, versioned pricing model (no longer one person's memory)
  • Full quote history logged for every job
Needs attention
  • Unusual/one-off jobs still fall back to manual judgment
  • No mobile-first flow yet for quoting on the shop floor
  • AI-suggested ranges need more historical data to stay accurate as material costs shift
Fig. 09 — Reflection

The hard part was never the interface.

The real design work was making one estimator's tacit judgment explicit enough to write down, disagree with, and improve — the app was just the last, easiest step once that was done.
