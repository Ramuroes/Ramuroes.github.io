00 Diagnosis

The direction is strong. It just isn't a system yet.

An honest read of the uploaded home, About, Work and case screens. The instincts are right and highly ownable — but decisions are being remade page by page. v1.0 exists to lock those decisions so every future page inherits them.

WORKING
  • 01

    An ownable core idea. The system-map hero shows operational design instead of describing it. Nobody else in this space looks like this.

  • 02

    Premium, technical-but-human tone. Editorial serif against mono technical labels lands mature and precise at the same time.

  • 03

    Confident dark-first restraint. No SaaS gloss, no gradient soup. The accent is used sparingly enough to still mean something.

  • 04

    Real, specific work. Metal workshop, e-commerce, edtech — grounded operations, not portfolio filler.

  • !

    Accent is inconsistent. Home is green, interior pages are orange, with no logic. It reads like two brands. The highest-priority fix — solved in §05.

  • !

  • !

  • !

01 Brand principles

Five commitments that decide everything else.

When two design options both look fine, these break the tie. They are the reason the system holds together.

01

Clarity is the product

Every artifact should make a complex thing easier to decide about. If it decorates without clarifying, it gets cut.

02

Systems, not screens

Design the structure first — inputs, flows, constraints, decisions. Screens are the last ten percent, and they inherit their logic from the map.

03

Grounded in real operations

Real processes, real constraints, real trade-offs. Never staged dashboards or invented numbers — the credibility is in the honesty.

04

Technical, but human

Precise like a lab, grounded like a workshop. Engineering rigor delivered by a person — not a faceless brand machine.

05

Restraint is the flex

Confidence shows in what's left out. One idea per view, one focus per screen, and generous silence around both.

02 Visual principles

How the brand becomes something you can see.

The brand principles, translated into rules a designer can apply without asking.

Blueprint, not neural net

The visual world is technical drawing — grids, nodes, dimension lines. Never particles, glow clouds or AI sparkle.

The grid is visible but quiet

Structure should be felt everywhere and shout nowhere. Patterns sit far below the content, never level with it.

One focus per view

Neutral is the default. Green marks the working path; orange marks the single decision. Never a rainbow.

Motion explains, never entertains

Things assemble and resolve. Nothing loops, bounces, or chases the cursor. If motion doesn't clarify, it's off.

Type carries the voice

Serif for human statements, sans for the product, mono for the machine. The mix is the personality.

Dark is the canvas

Light is a signal, spent sparingly. Because most of the screen stays dark, a single lit node reads as important.

03 Typography

Three voices, never blurred.

A serif for what a person says, a sans for what the product does, and a mono for what the machine records. Each has one job. Mixing their jobs is the fastest way to look generic.

05 Accent strategy · the core rule

Green is the system. Orange is the moment of decision.

This one rule fixes the split we found in the diagnosis. Green and orange are not two moods for two page types — they are two meanings that can live on the same screen. Neutral is the field. Green is the working, resolved path and every live signal. Orange marks the single point where a human has to decide, or where attention must go.

Neutral
The structure. Every node, line and surface that isn't doing something right now.
Green — the system
The working path, resolved states, live signals, brand primary, primary actions, success.
Orange — the decision
The one point of human judgement or attention. At most once per view.
USE NEUTRAL FOR
  • Structure & scaffolding
  • Inactive nodes / paths
  • Body, labels, dividers
  • Backgrounds & grids
USE GREEN FOR
  • Active / resolved path
  • Live & success states
  • Primary CTA · active nav
  • Brand primary accent
USE ORANGE FOR
  • The one decision node
  • Current step / selection
  • Point of human input
  • Interior wayfinding marker
DO
  • Let one accent lead per view; the other only points.
  • Keep orange to a single element on screen.
  • On text-heavy interior pages with no hero map, orange may carry section markers — nothing green competes there.
DON'T
  • Run green and orange at full strength in the same block.
  • Tint whole surfaces or fill large areas with either.
  • Switch the meaning by page — that's the split we're fixing.

07 Graphic grammar

One alphabet draws every diagram.

This is the fix for the two-unrelated-heroes problem. Every visual — hero, case diagram, background — is built from the same four primitives: nodes, connections, regions and annotations. Learn the alphabet once; every picture becomes a sentence in it.

01 · NODES

Things — inputs, steps, systems, people. Circles for entities, squares for processes.

02 · CONNECTIONS

Relationships — flow, dependency, boundary. Orthogonal by default, drawn on the grid.

03 · REGIONS

Boundaries — a scope, a phase, a system edge. Dashed outline, barely-there fill.

04 · ANNOTATIONS

Labels — IDs, dimensions, callouts. Always mono, always quiet, never decorative.

→ Rule: if a graphic can't be described as nodes + connections + regions + annotations, it doesn't belong to the brand. This is what keeps every diagram feeling like one hand drew it.

09 Connections & lines

Lines carry meaning, not decoration.

Four line styles, and each one says something specific. Connections turn at 90° on the grid, with a soft 4px corner. Diagonals are reserved for one thing only — decision branches.

Solid
Direct flow / dependency. The default connection.
Dotted
Loose / inferred link, or an axis / guide.
Active
The working / resolved path. Thicker, green, lit.
Branch
The only diagonal. A decision changing course.
DO · 90° TURN, SOFT CORNER
DON'T · RANDOM DIAGONALS
DO · LINES MEET NODE EDGE
DON'T · CROSS THROUGH NODES

→ Weights: 1px hairline guides · 1.4px standard connection · 1.7–1.8px active path. Junctions get a small dot; lines stop at the node's edge, never cross it.

10 Diagram language

Three diagram types cover every case.

Whatever the story, it fits one of three canonical layouts. Reusing them makes the work legible across cases — the reader already knows how to read the picture.

SHARED RULES
  • One reading direction, stated by layout.
  • Exactly one focus (orange) per diagram.
  • Snap every node to the 8px lattice.
  • Annotate corners with mono IDs & dimensions.
DENSITY
  • Hero: 6–10 nodes, generous space.
  • Case inline: 4–7 nodes, one idea.
  • Never more than ~12 — split instead.
  • When in doubt, remove a node.
11 Background patterns

Texture you feel before you notice.

Three background treatments, all built from the grid, all extremely low-contrast. They give surfaces a technical substrate without ever competing with content. If you can read the pattern before the words, it's too strong.

Dot lattice
Global page texture · ~5% dots
Blueprint grid
Hero / feature zones · ~5% lines
Column rules
Editorial / case body · vertical only
DO
  • Keep patterns at 4–7% opacity, fixed to the viewport.
  • Fade the pattern out under dense text.
  • Let real diagram nodes sit on the grid to tie them together.
DON'T
  • Stack two patterns in one zone.
  • Tint the pattern green or orange.
  • Animate or parallax the background.

17 Motion

Motion is a system becoming understandable.

Calm, intentional, explanatory. Structure appears first, then the path draws, then the decision lights, then the outcome resolves — the same order a person would reason through it. No particles, no bounce, no loops, no cursor-chasing. Everything below is real, running motion.

ON-LOAD ASSEMBLY · LIVE
1 · STRUCTURE

Nodes fade + scale in from 55%. Fast, staggered ~60ms. The skeleton arrives.

2 · PATH DRAWS

The green line strokes on left→right, ~0.9s, following the reading order.

3 · DECISION LIGHTS

The diamond pulses once to ~114% and settles. The eye is pulled to the choice.

4 · OUTCOME RESOLVES

The target node fills; labels fade up last. The system is now legible.

TIMING
  • Micro: 150–250ms
  • Reveal: 400–650ms
  • Assembly: 1.2–1.6s total
EASING
  • Enter: (.2,.7,.3,1)
  • Draw: (.3,.6,.2,1)
  • No overshoot > 1.15×
TRIGGERS
  • Assembly: once on load
  • Reveal: on scroll-in
  • Never on loop
REDUCED MOTION

All of it collapses to the final state, shown instantly. Nothing moves. Covered in §20.

19 Mobile behavior

Mobile-first, and the diagram simplifies.

On a phone the system doesn't shrink — it clarifies. Multi-branch maps collapse to a single vertical flow, node counts drop, and hover behaviours become resting states. The story survives; the density doesn't.

PRODUCT DESIGNER
Complexity into clarity.
INPUTS → DECIDE → RESOLVE
DIAGRAM → VERTICAL

Left→right flows rotate to top→bottom. One column, one path, at most one decision and one outcome.

TOUCH TARGETS ≥ 44PX

Buttons, nav and tappable nodes meet a 44px minimum. Node hit-areas grow invisibly to hold the target.

HOVER → RESTING STATE

No hover on touch. The active node and path show their lit state by default; tap navigates.

MOTION → ONCE, THEN STILL

Assembly plays a single time on the hero, shortened; scroll reveals stay subtle to protect battery and focus.

20 Accessibility

Clarity is only clarity if everyone gets it.

Non-negotiable. The dark-first palette is tuned to pass contrast, meaning is never carried by colour alone, and every motion has a still fallback.

CONTRAST
  • Body text ≥ 4.5:1; large text ≥ 3:1.
  • Green & orange used for large text / UI only.
  • Faint grey (#6E6F68) never below 15px.
NOT COLOUR ALONE
  • Shape + colour together (§08).
  • Decision = diamond, not just orange.
  • Status pairs a dot with its label.
FOCUS & KEYBOARD
  • Visible 2px green focus ring, 2px offset.
  • Logical tab order; skip-to-content link.
  • Diagrams get a text alt / caption.
REDUCED MOTION
  • prefers-reduced-motion honoured everywhere.
  • Assembly & reveals snap to final state.
  • No parallax, autoplay, or looping.

24 Implementation roadmap

From system to WordPress, in order.

A prioritized path to ship this on the Kadence child-theme foundation using only HTML, CSS, SVG and vanilla JS — no external animation libraries. Do them in sequence; each unblocks the next.

P1

Tokens as CSS variables in the child theme

Port §04–06 into :root custom properties in the Kadence child stylesheet — colors, surfaces, type scale, spacing, radii. Every later step references these.

FOUNDATION
P2

Global type, dark base & background pattern

Load Spectral / IBM Plex Sans / Mono, set the dark canvas, and add the fixed dot-lattice (§11) as a body pseudo-element. Lock heading, body and label roles globally so pages inherit voice.

THEME
P3

SVG diagram kit + reusable Kadence blocks

Build the node/line/region primitives (§07–10) as a small inline-SVG snippet library, then wrap the recurring components (§14, §22) as Kadence pattern blocks: work card, tag row, metadata strip, step indicator.

CORE WORK
P4

Home hero + one hero-map SVG

Assemble the split hero (§12) with the on-load assembly script (§17) — one small IntersectionObserver + CSS-transition file, reduced-motion guarded. Ship Home first as the reference implementation.

FLAGSHIP
P5

Case-study template on the 5-part spine

Build one WordPress template for the fixed case spine (§13), migrate the metal-workshop case into it, then Trazur and French Bakery. Replace any staged screens with abstracted diagrams.

CONTENT
P6

Work index, About, Contact + a11y pass

Complete the remaining pages (§23), then run the accessibility checklist (§20) across the site: contrast, focus order, alt text on diagrams, and a global prefers-reduced-motion audit before launch.

FINISH
TECHNICAL GUARDRAILS
· No JS animation libraries — CSS transitions + one IO helper · Inline SVG, never raster, for diagrams · Mobile-first breakpoints · All motion reduced-motion-guarded · Diagrams get text alternatives · Tokens are the single source of truth
